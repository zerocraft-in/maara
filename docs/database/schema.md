# Database Schema

**Status:** Phase 1 design. No migration has been applied — the local Supabase
stack cannot start in this environment (Docker is unavailable). This document is
the contract the Phase 2/4 migrations must implement. Migration filenames are
generated by the Supabase CLI and must never be invented by hand.

Conventions used throughout:

| Concern | Rule |
| --- | --- |
| Keys | `uuid` primary keys, `default gen_random_uuid()` |
| Tenancy | `organization_id uuid not null references organizations(id) on delete cascade` on every business table |
| Money | `bigint` integer **paise**; percentages and tax rates in **basis points** (`int`, 10000 = 100%) |
| Time | `timestamptz not null default now()` for `created_at`/`updated_at`; calendar dates as `date` |
| Audit columns | `created_by uuid references profiles(id)`, `updated_by uuid`, `created_at`, `updated_at` |
| Soft delete | Status/`archived_at` columns for catalogue records; hard delete only where history permits |
| Naming | `snake_case`, plural tables, singular column names, no reserved words |

## 1. Identity and tenancy

### `organizations`

| Column | Type | Rules |
| --- | --- | --- |
| `id` | uuid | PK |
| `name` | text | not null, 2–120 chars |
| `slug` | text | not null, unique, lowercase `[a-z0-9-]` |
| `currency` | char(3) | not null default `'INR'` |
| `timezone` | text | not null default `'Asia/Kolkata'` |
| `country` | char(2) | not null default `'IN'` |
| `gstin` | text | nullable |
| `address` | jsonb | structured address (line1, line2, city, state, postal_code) |
| `phone`, `email` | text | nullable |
| `logo_path` | text | Storage object path |
| `invoice_prefix` | text | not null default `'INV-'` |
| `invoice_next_number` | int | not null default 1, `check > 0` |
| `tax_inclusive_pricing` | boolean | not null default false |
| `created_at`, `updated_at` | timestamptz | not null |

### `profiles`

One row per `auth.users` row, created by a trigger on signup.

`id uuid pk references auth.users(id) on delete cascade`, `full_name text`,
`phone text`, `avatar_path text`, `default_organization_id uuid references
organizations(id) on delete set null`, `created_at`, `updated_at`.

Email is owned by `auth.users` and never duplicated into an exposed table.

### `stores` and `locations`

`stores` is the commercial sales entity used for reporting and channel
identity; `locations` is where stock actually lives. This is open decision D1 in
`docs/architecture/system-architecture.md`.

**`stores`**: `id`, `organization_id`, `name`, `code` (unique per org), `channel`
(`shop | van | online`), address fields, `is_active`, timestamps.

**`locations`**: `id`, `organization_id`, `store_id uuid null references stores`,
`name`, `code` (unique per org), `type`
(`shop | warehouse | van | online_fulfillment`), address fields, `is_active`,
timestamps. Constraint: `store_id` must belong to the same organization.

### `roles`, `permissions`, `role_permissions`

System roles are global reference rows, not per-tenant copies:

- `roles`: `id`, `key` (unique: `owner`, `admin`, `manager`,
  `inventory_staff`, `accountant`, `sales_staff`), `name`, `description`,
  `rank` (int, used to prevent privilege escalation), `is_system` (true).
- `permissions`: `key` PK (`products.read`, `inventory.adjust`,
  `purchases.receive`, `users.manage`, …), `group`, `description`.
- `role_permissions`: `(role_id, permission_key)` PK.

### `organization_members`

| Column | Type | Rules |
| --- | --- | --- |
| `id` | uuid | PK |
| `organization_id` | uuid | FK, cascade |
| `user_id` | uuid | FK `profiles(id)`, cascade |
| `role_id` | uuid | FK `roles(id)` |
| `status` | text | `invited \| active \| suspended` |
| `invited_email` | citext | nullable |
| `invited_by` | uuid | nullable FK `profiles(id)` |
| `invitation_token_hash` | text | nullable, never returned to clients |
| `invitation_expires_at` | timestamptz | nullable |
| `joined_at` | timestamptz | nullable |
| `created_at`, `updated_at` | timestamptz | not null |

Constraints: `unique (organization_id, user_id)`; one active owner minimum is
enforced by policy and RPC, not by a unique index.

## 2. Catalogue

### `categories`

`id`, `organization_id`, `parent_id uuid null references categories(id) on
delete restrict`, `name`, `slug`, `description`, `image_path`, `sort_order`,
`is_active`, timestamps. `unique (organization_id, slug)`; a category cannot be
its own parent (`check (parent_id <> id)`); cycles are rejected by trigger.

### `brands`

`id`, `organization_id`, `name`, `slug`, `logo_path`, `is_active`, timestamps.
`unique (organization_id, slug)`.

### `products`

`id`, `organization_id`, `category_id uuid null references categories on delete
set null`, `brand_id uuid null references brands on delete set null`, `name`,
`description`, `status` (`draft | active | archived`), `tax_rate_bps int not
null default 0`, `is_tax_inclusive boolean`, `created_by`, `updated_by`,
`created_at`, `updated_at`, `archived_at`.

### `product_variants`

`id`, `organization_id`, `product_id uuid references products on delete
restrict`, `sku text not null`, `barcode text null`, `size text`, `colour text`,
`cost_price_paise bigint not null check (>= 0)`, `selling_price_paise bigint not
null check (>= 0)`, `tax_rate_bps int null`, `reorder_point int not null default
0 check (>= 0)`, `is_active boolean`, timestamps.

Constraints: `unique (organization_id, sku)`; partial unique index on
`(organization_id, barcode) where barcode is not null`; product and variant must
share an organization (composite FK enforced by trigger).

## 3. Parties

### `suppliers`

`id`, `organization_id`, `name`, `contact_person`, `phone`, `email`,
`address jsonb`, `gstin`, `opening_balance_paise bigint not null default 0`,
`notes`, `is_active`, timestamps. `unique (organization_id, name)`.

### `customers`

`id`, `organization_id`, `name`, `phone`, `email`, `address jsonb`,
`opening_balance_paise bigint not null default 0`, `notes`, `is_active`,
timestamps. Partial unique index on `(organization_id, phone) where phone is not
null`.

Balances are derived from ledger/payment data; `opening_balance_paise` is the
only manually entered figure.

## 4. Inventory

### `inventory_balances`

`organization_id`, `location_id`, `variant_id`, `quantity int not null default 0
check (quantity >= 0)`, `average_cost_paise bigint not null default 0
check (average_cost_paise >= 0)`, `updated_at`. PK `(location_id, variant_id)`;
index on `(organization_id, variant_id)`.

This table is a **derived current state**. It is written only by trusted
database functions in `private` that also insert the movement. There is no
client update grant.

### `inventory_movements` (append-only)

| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid | PK |
| `organization_id` | uuid | FK |
| `location_id` | uuid | FK |
| `variant_id` | uuid | FK |
| `movement_type` | text | `purchase_receipt`, `sale`, `customer_return`, `supplier_return`, `adjustment`, `transfer_out`, `transfer_in`, `opening` |
| `quantity_delta` | int | non-zero; negative for outflows |
| `unit_cost_paise` | bigint | nullable, valuation at the time of movement |
| `reference_type` | text | `goods_receipt`, `order`, `return`, `stock_transfer`, `adjustment` |
| `reference_id` | uuid | source document |
| `transfer_id` | uuid | nullable, links out/in legs |
| `note` | text | required for manual adjustments |
| `created_by` | uuid | actor |
| `created_at` | timestamptz | not null |

Indexes: `(organization_id, variant_id, created_at desc)`,
`(organization_id, location_id, created_at desc)`, `(reference_type, reference_id)`.
Update and delete are blocked by trigger and by grants; corrections are made with
a compensating movement.

### `stock_transfers`

`id`, `organization_id`, `reference`, `from_location_id`, `to_location_id`,
`status` (`draft | in_transit | completed | cancelled`), `note`, `created_by`,
`completed_by`, `completed_at`, timestamps. Checks: locations differ; both belong
to the organization.

## 5. Purchasing

### `purchase_orders`

`id`, `organization_id`, `supplier_id`, `location_id` (receiving destination),
`reference` (unique per org), `status` (`draft | submitted | partially_received |
received | cancelled`), `order_date date`, `expected_date date`, `subtotal_paise`,
`discount_paise`, `tax_paise`, `total_paise`, `notes`, `created_by`,
`approved_by`, timestamps.

### `purchase_order_items`

`id`, `organization_id`, `purchase_order_id`, `variant_id`, `quantity int
check (> 0)`, `received_quantity int not null default 0`, `unit_cost_paise
bigint`, `discount_bps int`, `tax_rate_bps int`, `line_total_paise bigint`.

`received_quantity` is maintained inside the receiving transaction; it can never
exceed `quantity`.

### `goods_receipts` / `goods_receipt_items`

`goods_receipts`: `id`, `organization_id`, `purchase_order_id`, `location_id`,
`reference`, `received_at`, `received_by`, `note`, timestamps.

`goods_receipt_items`: `id`, `organization_id`, `goods_receipt_id`,
`purchase_order_item_id`, `quantity int check (> 0)`, `unit_cost_paise bigint`.

## 6. Sales

### `orders`

`id`, `organization_id`, `order_number` (unique per org), `location_id`,
`store_id`, `channel` (`shop | van | online`), `customer_id uuid null`,
`status` (`completed | void`), `payment_status` (`unpaid | partial | paid |
refunded`), `subtotal_paise`, `discount_paise`, `tax_paise`, `total_paise`,
`paid_paise`, `refunded_paise`, `placed_at`, `idempotency_key` (nullable, unique
per org), `created_by`, timestamps.

### `order_items`

`id`, `organization_id`, `order_id`, `variant_id`, `quantity int check (> 0)`,
`unit_price_paise`, `unit_cost_paise` (cost snapshot for margin reporting),
`discount_bps`, `tax_rate_bps`, `line_total_paise`.

### `payments`

`id`, `organization_id`, `order_id uuid null`, `purchase_order_id uuid null`,
`direction` (`inflow | outflow`), `method` (`cash | card | upi | bank |
credit_note`), `amount_paise bigint check (> 0)`, `reference`, `paid_at`,
`created_by`, timestamps. Check: exactly one of `order_id`/`purchase_order_id` is
present.

### `returns` / `return_items`

`returns`: `id`, `organization_id`, `order_id`, `location_id`, `reference`,
`reason`, `status` (`draft | completed | cancelled`), `total_paise`,
`restock boolean`, `created_by`, `completed_at`, timestamps.

`return_items`: `id`, `organization_id`, `return_id`, `order_item_id`,
`quantity int check (> 0)`, `unit_price_paise`, `line_total_paise`,
`restock boolean`.

Cumulative returned quantity may not exceed the sold quantity; enforced in the
completion function.

## 7. Expenses and finance

### `expense_categories`

`id`, `organization_id`, `name`, `is_active`, timestamps.
`unique (organization_id, name)`.

### `expenses`

`id`, `organization_id`, `expense_category_id`, `supplier_id uuid null`,
`location_id uuid null`, `amount_paise bigint check (> 0)`, `expense_date date`,
`payment_method`, `reference`, `notes`, `attachment_path`, `created_by`,
timestamps.

### `financial_transactions` (append-only ledger)

`id`, `organization_id`, `occurred_at timestamptz`, `direction` (`inflow |
outflow`), `amount_paise bigint check (> 0)`, `source_type` (`sale`, `purchase`,
`expense`, `payment`, `refund`, `adjustment`, `opening`), `source_id uuid`,
`description`, `created_by`, `created_at`.

Indexes: `(organization_id, occurred_at desc)`, `(organization_id, source_type,
source_id)`.

## 8. Audit and notifications

### `audit_logs` (append-only)

`id`, `organization_id`, `actor_id uuid null`, `action text`, `entity_type text`,
`entity_id uuid null`, `summary text`, `before jsonb`, `after jsonb`,
`ip inet`, `user_agent text`, `created_at timestamptz`.

No update/delete grants for any client role. Writes come from triggers and
privileged functions only.

### `notifications`

`id`, `organization_id`, `user_id`, `type`, `title`, `body`,
`entity_type`, `entity_id`, `read_at timestamptz null`, `created_at`.

## 9. Index policy

Every table gets:

1. A PK index.
2. An index beginning with `organization_id` for the dominant listing query
   (`(organization_id, created_at desc)` or status variants).
3. Indexes on all FK columns used for joins or cascade checks.
4. Partial indexes for soft-deleted/active filters where queries need them.
5. `pg_trgm` GIN indexes for product/customer/supplier name search only after
   query plans justify them.

No index is added speculatively without a matching query in the codebase.

## 10. Deletion behaviour

| Relationship | On delete |
| --- | --- |
| Organization → all business rows | cascade |
| Profile deletion (auth user) | memberships cascade; historical `created_by` set null |
| Category → products | set null (category archive is preferred) |
| Product → variants | restrict (archive product instead) |
| Variant → order/purchase lines | restrict |
| Supplier/customer → documents | restrict |
| Movement/receipt/return/ledger rows | restrict, never cascade |

## 11. Migration stages

The CLI generates timestamped filenames. The logical order is:

```text
001_extensions_and_common_functions
002_organizations_stores_locations
003_profiles_memberships_roles_permissions
004_catalog
005_suppliers_customers
006_inventory
007_purchases_and_receiving
008_sales_payments_and_returns
009_expenses_and_financial_transactions
010_audit_logs_and_notifications
011_storage_buckets_and_policies
012_reporting_views_and_indexes
```

Each migration must be reviewed for FKs, constraints, indexes and RLS before it
is applied. `supabase db reset` and the pgTAP suite must pass locally first, and
nothing is pushed to a hosted project without explicit approval.
